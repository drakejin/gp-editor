# gp-editor — agent rules

Guitar Pro editor desktop app. TypeScript + React + React Native (react-native-macos).
Goal: read every Guitar Pro file — GP1/GP2 (.gtp), GP3 (.gp3), GP4 (.gp4), GP5 (.gp5), GP6 (.gpx), GP7/GP8 (.gp).
It also imports Power Tab (.ptb), TablEdit (.tef) and Standard MIDI Files (.mid, .midi).
MusicXML (.musicxml / .xml, compressed .mxl) is read and written too.

## Layout

| path | what |
| --- | --- |
| `packages/gp-core/` | Pure TypeScript, no React. Format detection, readers, writer, song model, edits, MIDI, PDF transcription → song. Runs in Node (tests) and Hermes (app) — no Node APIs; never rely on a global TextDecoder (Hermes has none: `io/text.ts` decodes UTF-8 and windows-1252 itself and tries one, when present, only for other code pages). |
| `packages/gp-core/src/` (top level) | `index.ts` = the public API (the app imports only from it); `read-song.ts` (`readSong`); `errors.ts`; `formats/detect.ts` (`detectFormat`, by content); `formats/options.ts` (`ReadOptions`, charset). |
| `packages/gp-core/src/model/` | `song.ts` = the format-independent model every reader returns (a `Duration` may hold an `innerTuplet`: a tuplet inside its tuplet, GP7/GP8's secondary tuplet; a `Track` may hold `effects`, a `Song` a `master` mix: the app's playback effects; a `Track` may hold Guitar Pro's `shortName` and `iconId`, absent = derived). `defaults.ts` = constants and tick helpers, and why `QUARTER_TIME` is what it is; `roundTempo` (a tempo keeps two decimals) and `toNoteAudio` (a note's audio settings, `Note.audio`: play duration %, start offset %, velocity change — playback only); `MAX_VOICES` (4) and `EMPTY_VOICE`; `FOUR_FOUR`, `headerTicks` (a header's bar length), `clamp`, `isHairpin`. |
| `packages/gp-core/src/io/` | `ByteReader` (little-endian cursor, GTPInputStream-style string helpers), text decoding and encoding (`text.ts`: UTF-8 and windows-1252 both ways, one home for both tables). |
| `packages/gp-core/src/formats/common/` | Guitar Pro facts shared by both reader families: GM channel names and bass programs (`channels.ts`, also the 128 GM instrument names and 16 families of the instrument picker, the banjo program, GM percussion names `gmPercussionName` and the drum kit's keys `GM_DRUM_KEYS`), harmonic table, velocity scale, bend/whammy units, the musical directions (`directions.ts`: GP5's 19 slots, GPIF's names) and rasgueado patterns (`rasgueado.ts`: GPIF ids, fingers, rhythm), GP3–GP5's codes the readers read and the writers write (`gtp-codes.ts`: tuplets, stroke / trill / tremolo picking bytes, grace transitions); Guitar Pro 7/8's instrument sets (`instrument-sets.ts`: `instrumentSetOf`, a GM program's `<InstrumentSet>` and icon) and track icons and colours (`track-icons.ts`: `TRACK_ICON_IDS` — GPIF `<IconId>`s by what they show —, `trackIconName`, `isTrackIconId`, `TRACK_COLORS` — Guitar Pro 8's track colours); Guitar Pro 7's factory drum kit (`drum-kit.ts`: elements, articulations, staff lines, noteheads, technique symbols, input / output MIDI numbers — the .gp writer writes it) and `drum-notation.ts` (`drumNotation(key)`: a drum note's staff position in the app's steps, SMuFL noteheads per note value, technique symbol and placement, GM key played, element and articulation; `DRUM_KIT_NOTATIONS` the whole kit); `song-draft.ts` = the song the Power Tab and TablEdit readers build step by step (TuxGuitar's TGSongManager parts they use), then turn into a `Song`. |
| `packages/gp-core/src/formats/gtp/` | GP1–GP5 binary readers: `gp3.ts`–`gp5.ts` (+ `gp5-notes.ts`) on GP3–GP5's shared parts — `shared.ts` (reading context, song info, the measures into a song), `gtp-channels.ts`, `gtp-tracks.ts`, `gtp-beats.ts`, `gtp-note-effects.ts`; `gp1.ts` / `gp2.ts` on `legacy-shared.ts` (song, tracks, beats laid out) + `legacy-measures.ts` + `legacy-beats.ts` + `legacy-duration.ts`. |
| `packages/gp-core/src/formats/gpif/` | GP6 (.gpx, BCFZ/BCFS container) and GP7/8 (.gp, zip) — both hold a GPIF XML document. XML (GPIF and MusicXML): `xml.ts` (`parseXmlDocument`, the element helpers); a plain document — one XMLValidator accepts, read as fast-xml-parser reads it — goes through `xml-tree.ts` + `xml-tag.ts` in one pass, anything else through XMLValidator and fast-xml-parser (`XML_PARSER_OPTIONS`). |
| `packages/gp-core/src/formats/ptb/` | Power Tab (.ptb, version 4), port of TuxGuitar's `TuxGuitar-ptb`: `ptb-input-stream.ts` + `ptb-section-reader.ts` (+ `ptb-byte-reader.ts`, MFC object arrays) read the guitar and bass scores into `ptb-model.ts`; `ptb-synchronizer.ts` plays repeats, endings and D.C./D.S./coda jumps out (a loop, bounded); `ptb-song-parser.ts` lays the staffs' voices on one timeline (`track-start-helper.ts`) and gives each staff the track its Guitar In names (`track-info-helper.ts`). Not in TuxGuitar: measures take their bar's time signature. |
| `packages/gp-core/src/formats/tef/` | TablEdit 3 (.tef), port of TuxGuitar's `TuxGuitar-tef` tef3 reader: `tef-header.ts` (detection), `tef-input-stream.ts`, `tef-components.ts` (12-byte components, positions on a 64th grid), `tef-song-parser.ts` + `tef-components-to-song.ts` + `tef-note-effects.ts`, `tef-song-adjuster.ts` (fits beats into the measure, voice by voice). Fixes over TuxGuitar (from the real files): the tag's byte order, the 64th grid, triplet runs (`tef-timeline.ts`), tunings without the capo, rest lengths. TablEdit 2 files (no header to detect) are not read. |
| `packages/gp-core/src/formats/midi/` | Standard MIDI File import, a port of TuxGuitar's `MidiSongReader` (`midi-song-reader.ts`, `readMidiSong(bytes, settings)`; `toSongTick` scales the file's division to `QUARTER_TIME` exactly): `midi-file-reader.ts` (bytes → `MidiSequence`; chunk lengths, running status, 4-byte VLQs, event count and ticks checked, `MIDI_LIMITS`), `midi-headers.ts` (tempo, meter, key events → measure headers, at most `MAX_MEASURES`), `midi-track-parser.ts` + `midi-quantize.ts` (note on/off → beats, tied across bar lines; format 0 split by channel), `duration-split.ts` + `precise-duration.ts` (TGDuration's precise-time quantisation; a precise unit is a whole number of song ticks), `midi-channels.ts`, `midi-strings.ts` (standard guitar / bass tuning when the notes fit, else TuxGuitar's tunings; notes onto strings with `edit/string-placement.ts`, drums by TGDrumMap), `midi-measures.ts` (rests to the bar line), `midi-settings.ts` (MidiSettings: transpose, quantisation, shortest duration, tuplets). MIDI output stays in `src/midi/`. |
| `packages/gp-core/src/formats/musicxml/` | MusicXML import (our own; TuxGuitar has no reader): `musicxml-document.ts` (text, no DTD subsets, score-timewise converted), `musicxml-container.ts` (.mxl), `musicxml-measures.ts` (a part's measures, divisions scaled exactly to `QUARTER_TIME`), `musicxml-staves.ts` (a notation staff paired with a tab staff), `musicxml-voices.ts`, `musicxml-placement.ts` (pitches onto strings with `edit/string-placement`), `musicxml-effects.ts`, `musicxml-headers.ts`, `musicxml-track.ts`; limits in `musicxml-values.ts`. |
| `packages/gp-core/src/edit/` | Immutable edit operations on a `Song`: notes (`setNoteFret` — in an empty voice it fills the voice with rests to the bar lines, `voice-entry.ts` —, `setNoteString`, `setNoteVelocity`, `deleteNote`, `toggleNoteEffect`, ties; bends and tremolo bar with TuxGuitar's presets, slight / wide vibrato (`setNoteVibrato`), harmonics in `effects.ts`; bend shapes at any amount (`buildBend`, `bendShapeOf`) in `bend-shapes.ts`; a curve edited point by point (`addCurvePoint`, `moveCurvePoint`, `removeCurvePoint`, `normalizeCurvePoints`: one point per position on the 0–12 × quarter-tone grid) in `curve-points.ts`; grace notes, trills, tremolo picking in `ornaments.ts`), beats (`setBeatDuration`, `insertBeat`, `deleteBeat`, `deleteBeatNotes` — over a run of beats `deleteRunNotes`, `run-notes.ts` (or only its notes on some strings): the beats stay as rests, a tie after the run left with nothing to continue undone (`untieOrphanNotes`, `ties.ts`, which Move Voice uses too) —; stroke, pick stroke, text in `beat-attributes.ts`; copy, cut and paste of a run of beats in `beat-ranges.ts` — `copyBeats` lifts a `BeatFragment` (`beat-fragment.ts`), `deleteBeatsFlowing` / `insertBeatsFlowing` move what follows and re-bar the voice to the end (`bar-flow.ts`; a note across a bar line becomes tied notes, `tied-pieces.ts`), `parseBeatFragment` / `serializeBeatFragment` check and write the clipboard's JSON, `fragment-json.ts`), measures (`insertMeasure`, `deleteMeasure`, `deleteMeasures` — a run of bars in one edit —, `fillEmptyMeasure` — rests to the bar line in a bar without beats, where a track rests; beat 0 of such a bar is its start for `copyBeats` / `deleteBeatsFlowing` / `insertBeatsFlowing`) and measure headers (time signature, tempo — two decimals —, key, repeats, marker, triplet feel), a note's audio settings (`setNoteAudio`, `note-audio.ts`), a blank song (`buildNewSong`), song information (`song-info.ts`), a track's sound (`track-sound.ts`: program, volume, balance, mute, solo; a track sharing its channel gets a copy) and properties (`track-properties.ts`: name, short name, colour, icon, capo; `trackShortName` — its own, else `abbreviateTrackName` —, `trackIconId` — its own, else `instrumentIconId`, the instrument set's, a voice for a track named like one —; a file's short name equal to the name or its abbreviation and an icon equal to the instrument's are none, `normalizeShortName` / `normalizeIconId`, as the edits keep them; GPIF and MusicXML `part-abbreviation` read and write them, GP3–GP5 the colour only). Beat edits may leave a measure over-full (`isMeasureOverfull`), never drop notes (`timeline.ts`, `voice-fit.ts`, `rests.ts` — rests plain, in a tuplet or in the tuplet inside it —, `relayout.ts`). Addresses: `BeatAddress` / `StringAddress` (`addresses.ts`). Tuning: `tuning-presets.ts` (guitar/bass/banjo presets, `resolveInstrument`), `banjo.ts` (the 5-string banjo's short 5th string: stored from its peg, shown from the nut — `tabFret` / `fretFromTab`), `string-placement.ts` (one beat's notes onto strings; `stringsNearHand` for notes played together), `tuning-fit.ts` (`canPlayOnTuning`, `suggestTunings` / `suggestTrackTunings` for the `NECK_FRETS`-fret neck), `retune.ts` (`setTrackTuning` re-frets every note to keep its pitch, counting octave moves and notes left out). Note entry: `pitch-entry.ts` (`enterPlayedNotes`, MIDI step entry), `drum-notes.ts` (`toggleDrumNote`; a drum note's fret is its GM key, up to `MAX_DRUM_KEY`). Transposition: `transpose.ts` (`transpose(song, scope, options)`: a selection, a track or the song, by semitones or scale steps; `transpose-beat.ts` one beat and the ties that follow, `transpose-placement.ts` moving notes onto the strings the others leave free — a note that fits nowhere stays and is counted), `key-spelling.ts` (a pitch spelled in a key signature, scale steps, `transposeKeySignature`; the natural notes' letters and pitch classes, `NOTE_LETTERS` / `letterPitchClass`, for chords, scales and transcription too), `chord-transpose.ts` (chord names' root and bass, diagrams on the same strings). |
| `packages/gp-core/src/edit/` (voices) | Voices 1–4 of any bar: a slot a beat lacks below the fourth (voices 3–4 of a bar read from GP3–GP5) is an empty voice (`voiceOf`, `findVoice`, `locateVoice` in `addresses.ts`), and `toMeasureVoices` gives the beats the slot an edit needs, so every cursor edit works in voices 3–4. `voice-moves.ts`: `moveNotesToVoice` / `moveBeatsToVoice` (Guitar Pro 8's Move Voice: notes to another voice at the same time and length, into an event of that length, an empty voice or free rests — `placeVoiceEvent` in `voice-entry.ts`; a run moves whole or not at all; ties left with nothing to continue are undone). GP5 writes voices 1–2, GP4/GP3 join every voice into voice 1, `.gp` and MusicXML keep four. |
| `packages/gp-core/src/edit/notation-marks.ts` | Notation marks (no TuxGuitar counterpart): `setNoteFinger` (left / right hand; a keyboard's piano fingering is the left hand's), `setNoteAccidentalDisplay` (cautionary / forced), `setVoiceSlashed`, `setVoiceBeamToNext` (break / join / break secondary beams), `setTrackSlashNotation`, `setBeamGrouping` (the bar and the bars after it grouped alike). `model/beaming.ts`: a bar's beam grouping (the time signature's own, presets, bounds in ticks, `parseBeamGrouping` for files). Files: `formats/common/fingering.ts` (GP3–GP5 bytes, GPIF letters P I M A C), `formats/gpif/part-configuration.ts` (the PartConfiguration's slash flag), `formats/gtp/gp5-beams.ts` (GP5's beam bytes and beat display flags, kept on the beat after the beam). |
| `packages/gp-core/src/edit/tracks.ts` | Track edits (TuxGuitar's TGSongManager track parts): `addTrack(song, NewTrack)` (a kind of `track-kinds.ts` — guitar 6/7/8, bass 4/5/6, banjo, ukulele, drums, keys, other GM programs — with TuxGuitar's tunings.xml tunings, `trackTuningChoices`; its own channel, `nextChannelId`, drums on the percussion bank; rests under every header, `measures.ts`' `restMeasure`), `deleteTrack` (never the last; an unplayed channel goes), `duplicateTrack` (right after, a copy of its channel), `moveTrack`, `hasTrackNotes`. `track-index-map.ts`: `TrackIndexMap` (old index → new, undefined = deleted), `remapTrackIndex(es)`, `matchTrackIndexes(before, after)` (tracks found by their `measures` array, which track edits keep: what undo / redo follow). |
| `packages/gp-core/src/edit/lyrics.ts` | A track's lyrics: `setTrackLyrics` (text and first bar; a blank text removes them), `lyricsSyllables` (Guitar Pro's syllables: spaces and line breaks, hyphens; `+` joins words on one note, trailing `_` and `[comments]` left out — the score's lyrics use it), `separateCjkSyllables` (one Korean / Japanese / Chinese character per note). |
| `packages/gp-core/src/annotations/` + `edit/annotations.ts` | A musician's annotations (the app's own; no TuxGuitar counterpart, no Guitar Pro file holds one; not Guitar Pro's one-line beat `text`, which is notation): `Beat.annotation` (`Annotation`: a few lines of text, bounded by `annotation-text.ts` — `normalizeAnnotationText`, `toAnnotation` —, placed above or below the staves). Edits `setBeatAnnotation` (a bar without beats gets its rests first), `moveBeatAnnotation` (never onto a beat that has one), `songAnnotations`, `withoutAnnotations` (an export that leaves them out). The annotation goes with its beat: edits carry it with the beat's other marks (`edit/timeline.ts`; an annotated rest is no free time), cut / copy / paste in the clipboard fragment (`fragment-json.ts` checks it). Files: `song-annotations.ts` (a .gp file keeps them as our entry `Content/GPEditor/notes.json`: track, bar and place in the bar in ticks; untrusted JSON bounded, `MAX_FILE_ANNOTATIONS`); GP3–GP5 leave them out; MusicXML writes boxed `<words enclosure="rectangle">` (its reader reads such words as beat text, as any words). |
| `packages/gp-core/src/edit/marks.ts` | Notation marks (no TuxGuitar counterpart; model: `MeasureHeader.directions`, `Beat.hairpin` / `rasgueado`, `Measure.pedals`, `NoteEffect.fadeOut` / `volumeSwell`): `toggleDirection` (a bar's targets and jumps), `toggleHairpin` (over a run of beats — runs between two addresses in `beat-runs.ts`, which `setOttava` and Move Voice use too), `setBeatRasgueado`, `toggleBeatPedal`; fades in `toggleNoteEffect` (one fade per note). ## Conventions

- Reference implementation: TuxGuitar (`../tuxguitar`, LGPL-2.1). Readers are ports of its
  `common/TuxGuitar-gtp` and `common/TuxGuitar-gpx` modules; each ported file starts with a
  one-line comment naming the TuxGuitar class it follows. gp-core is therefore LGPL-2.1-or-later.
- Model objects are `readonly`. Readers build fresh objects; never mutate a model object after creating it.
- Strict TS (`noUncheckedIndexedAccess`). No `any`, no `console.log`. Functions < 50 lines, files < 800 lines.
- Bend / tremolo-bar values are in quarter tones, positions 0–12 (TuxGuitar's TGEffectBend units).
- Strings are numbered from 1 = highest string. Ticks: `QUARTER_TIME` (960 × 135135) per quarter note, so every duration
  Guitar Pro writes (7, 9, 11, 13-tuplets and a tuplet inside a tuplet too) is a whole number of ticks (`model/defaults.ts`).
  Tests write positions in TuxGuitar's 960ths: `fromTux` / `toTux` (`test/helpers/ticks.ts`, `apps/desktop/test-support/songs.ts`).
- Tests: Vitest, AAA, descriptive names. Every reader has a fixture sweep (all files in its folder parse
  and pass `assertSongInvariants`) plus value checks for specific files.

## Naming (one vocabulary for the whole repo)

- **Model words come from `src/model/song.ts`**: song, track, measure + measure header (GPIF's raw `<MasterBar>`/`<Bar>` keep
  their names only inside `formats/gpif`), beat, voice, note, string, fret, tempo, `velocity` (MIDI value; the raw Guitar Pro
  value is a `dynamic`), `channelId` (model) vs `gmChannel` (raw MIDI channel in the file).
- **0-based positions end in `Index`** (`trackIndex`, `Measure.headerIndex`, `BeatAddress.measureIndex`);
  **1-based musical numbering is `number`** (`Track.number`, `MeasureHeader.number`, `GuitarString.number`, `trackNumber`).
- **Verbs**: `read*` consumes bytes/XML; `parse*` interprets one already-extracted raw value; `build*` assembles model
  objects; `to*` / `*From*` are pure conversions; `resolve*` picks among fallbacks; `set*` / `insert*` / `delete*` / `toggle*` are gp-core
  edits that return a new `Song`. An editor action that runs one gp-core edit as it is takes its name (`setNoteFret`,
  `deleteNote`, `insertBeat`); a relative step is `shift*` (`shiftNoteFret`, `shiftNoteString`, `shiftTempo`), a flip
  `toggle*`, a rotation `cycle*` (`cycleBend`).
- **Booleans** `is*` / `has*` / `can*`. **Constants** `UPPER_SNAKE_CASE`, including grouped objects (`TAB`, `FRET_BOX`).
- **Files**: modules are kebab-case (`byte-reader.ts`, `fret-input.ts`); React components are PascalCase (`ScoreRow.tsx`);
  a test file is named after the module it tests (`fret-input.test.ts`), prefixed with its folder when nested
  (`edit-beats.test.ts`, `pdf-import-run.test.ts`). Exception: codegen specs must be named
  `*NativeComponent.ts` (`src/native/specs/`).
- **Score drawing**: the score is never built from one React view per glyph. Engravers return `DrawCommand`s and the
  native `GPScoreCanvas` draws a whole row; music symbols are SMuFL code points of the bundled Bravura font (`SMUFL` in
  `draw.ts`).
- **One home per fact**: shared Guitar Pro facts in `formats/common`, model helpers (`durationTicks`, `durationFromTicks`,
  `NOTE_VALUES`) in `model/defaults.ts`; never re-declare them in a reader. Tables keyed by text from a file are read with
  `lookupName` (own properties only).
- **App**: props interfaces are `XxxProps`; callbacks are `onXxx`; `palette` is passed as a prop below `App`
  (only `App`'s `useWindow` calls `usePalette()`); notification names shared by Swift and Objective-C live in `GPEditorNotifications.h`.
  One helper per app-wide wording: `errorMessage` (`lib/errors.ts`), `plural` (`lib/wording.ts`).
- **App text**: every string the app shows comes from `src/lib/i18n` (`useT()` in components, `t()` in helpers; English
  first, Korean in the words of `lib/i18n/glossary.md`); a new string is a key in both `en/` and `ko/`. Notation on the
  score (P.M., let ring, 8va, dynamics, chord and note names) stays as written.
