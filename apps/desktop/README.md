# gp-editor desktop

React Native 0.83 app with the macOS target from react-native-macos 0.83 (`macos/`). Opens Guitar Pro files through
`@gp-editor/core` (linked from `../../packages/gp-core`, bundled from source by Metro).

## QA driver

`scripts/qa/run.sh <script.json>` copies the Release app to `macos/build/qa/GPEditor-QA.app` (again when the build is
newer), re-signs it with `GPEditor-QA.entitlements` (no App Sandbox), runs it with `GPEDITOR_QA_SCRIPT=<script.json>`,
waits up to 180 s for it to quit and prints `<script.json>.log`. `GPQADriver.m` starts 3 s after launch and runs the
steps in order; points are in the window's content view, origin top-left:

- `{"open": "/abs/file"}` hands a file over as Finder does
- `{"notify": "GPEditorExportCommand"}` posts a menu notification (`GPEditorNotifications.h`); `"object"` is passed
  along (e.g. the score mode of `GPEditorNewCommand`)
- `{"wait": 1500}` · `{"click": {"x": 300, "y": 200}}` (the mouse-up is queued first, so a click into a text field works) · `{"rightClick": {"x": 300, "y": 200}}` (a view's `onAuxClick`; react-native-macos takes its place from the real pointer, so the window moves for a moment to put the point under it, and the log says where the pointer was) · `{"controlClick": {"x": 300, "y": 200}}` (a ⌃-click: a Pressable's press with `ctrlKey`) · `{"drag": {"from": {"x": 300, "y": 200}, "to": {"x": 500, "y": 420}, "steps": 8}}` (do not send Escape into a focused text field: AppKit rejects the synthetic event and the app aborts) · `{"scroll": {"x": 600, "y": 400, "dy": -300}}`
- `{"hover": {"x": 300, "y": 200}}` the mouse entering the views at a point (each view there with a tracking area gets
  `mouseEntered:` — a Pressable's `onHoverIn`; synthetic mouse moves never reach tracking areas)
- `{"key": "z", "modifiers": ["cmd", "shift", "alt", "ctrl"]}` — ArrowUp/Down/Left/Right, Backspace, Delete, Escape,
  Enter, Tab, else the character
- `{"resize": {"width": 1100, "height": 760}}` · `{"appearance": "dark"}` (anything else is light)
- `{"menu": ["File", "Open Recent"]}` logs the items of a menu-bar menu; `{"menu": ["File", "Open Recent", "Song.gp5"]}`
  chooses the item, as a click in the menu does
- `{"focusRoot": true}` makes the largest focusable view first responder · `{"inspect": true}` logs the responders
- `{"snapshot": "/abs/out.png"}` · `{"quit": true}`

MIDI input needs no QA step: a virtual CoreMIDI source (`MIDISourceCreate` + `MIDIReceived` in a small Swift script run
next to the app) shows up as a source and plays notes into it.

Only the unsandboxed QA copy honours `GPEDITOR_ANTHROPIC_URL` (PDF-import requests to a mock on `http://127.0.0.1` or
`http://localhost`), `GPEDITOR_QA_PDF_PATH` (the PDF export saves there without the save panel),
`GPEDITOR_QA_PRINT_PATH` (File ▸ Print… saves the print job there as a PDF, without the print panel),
`GPEDITOR_QA_SAVE_PATH` (Save As, Export MIDI… and Export ASCII Tab… save there without the save panel, in the offered
format with that path's extension) and `GPEDITOR_QA_PNG_DIR` (File ▸ Export PNG… writes its images into that folder,
without panels). File ▸ Export Audio… saves one file at `GPEDITOR_QA_SAVE_PATH` too (give it the chosen format's
extension) and one file per track into `GPEDITOR_QA_AUDIO_DIR` (no folder panel, no replace question); open the panel with
`{"notify": "GPEditorExportAudioCommand"}`. The QA copy has no sandbox, so the security-scoped bookmarks of the recent files are made and
resolved but never needed there.
It also honours `GPEDITOR_QA_TUNER_HZ=<Hz>`: the tuner hears a synthetic plucked tone at that frequency through the
same decimation instead of the microphone (no microphone, no permission prompt); open the tuner with
`{"notify": "GPEditorTunerCommand"}`.
And `GPEDITOR_QA_LINE_IN_HZ=<Hz>`: Tools ▸ Line In… plays a sine at that frequency (−12 dBFS) in place of the audio
input, without asking for microphone access; open it with `{"notify": "GPEditorLineInCommand"}`, the mixer with
`{"notify": "GPEditorMixerCommand"}`.
Expression Text opens with `{"notify": "GPEditorCommandPaletteCommand", "object": "expression"}` (the command palette
without the object).
View ▸ Multitrack, Previous Track and Next Track: `{"notify": "GPEditorMultitrackCommand"}`, `GPEditorPreviousTrackCommand`, `GPEditorNextTrackCommand`.
And `GPEDITOR_QA_AUDIO_PATH=<file>`: Track ▸ Add Audio Track… takes that audio file without the question or the open
panel (`{"menu": ["Track", "Add Audio Track…"]}` or `{"notify": "GPEditorAddAudioTrackCommand"}`).
The Track menu's track commands need no QA hook: `{"notify": "GPEditorTrackCommand", "object": "add"}` (or `duplicate`,
`delete`, `moveUp`, `moveDown`) does what the menu item does.

## Notes

- `macos/.xcode.env.local` (git-ignored) pins `NODE_BINARY` for the Xcode bundle phase; point it at Node 24.
- The app is sandboxed (`GPEditor.entitlements`: App Sandbox, user-selected read-write files, network client — Metro
  in Debug, `api.anthropic.com` for the PDF import —, read-write `~/Documents/GP Editor Projects/` as a
  home-relative temporary exception, and app-scoped security bookmarks for the recent files). Files reach it through
  the open and save panels, drag and drop, Finder, the recent files, or that projects folder. Release builds do not get `get-task-allow`.
- The microphone (`com.apple.security.device.audio-input`, with `NSMicrophoneUsageDescription` in `Info.plist`) is
  used only by the tuner, only while its panel is open; nothing is recorded or kept.
